# Kuyo Privacy Policy

Effective: October 16, 2026

Kuyo is a Discord bot that reads selected text messages aloud and provides optional social-link previews, enabled by default per server. It also contains an optional character-reply feature for messages that call Kuyo, which the service operator may enable or disable, an optional message translation that the service operator may enable and each server can turn off, mini-games any member can open with the `/game` command, and formatted posts that server managers write on the settings website. Kuyo is configured on that website. This policy explains what information Kuyo uses and how it is handled.

## Information we use

Kuyo uses only the information needed to provide its features:

- Discord server, channel, user, and original/preview message IDs
- Server settings, voice preferences, custom join greetings and leave farewells, and custom pronunciation entries
- Messages posted in the TTS channels selected by a server administrator; in a voice channel's built-in chat, only messages from members in that voice channel are read
- Supported public-post URLs in accessible server channels when link previews are enabled
- When the optional character-reply feature is enabled, the text of messages that call Kuyo, and the number of images attached to them: a mention of Kuyo or of one of her roles, or a reply to one of her messages, even with the reply ping turned off
- When the optional character-reply feature is enabled and someone calls Kuyo, the recent messages of that channel or thread, with their authors' server display names, as described below
- When the optional translation feature is enabled, the text of a message a member chooses to translate with `Translate with Kuyo`; for a message without text, the text of what it forwards or the title and description of its cards
- The translation language a member chooses on the settings website
- Display names and the names of mentioned users, roles, or channels when needed to read a message naturally
- The pages (tab names, titles, bodies, and images) and link buttons of posts a server manager writes on the settings website
- While a word-chain game is running, messages posted in that channel, so that a word played into the game can be judged
- If you turn on Kuyo memory, short facts about you that Kuyo picked from your conversations with her
- When you sign in to the settings website, your Discord user ID and the IDs of the servers you belong to

Kuyo does not collect passwords, payment information, contacts, or direct messages. Outside the selected TTS channels, Kuyo checks supported URLs when link previews are enabled and processes messages that call Kuyo, together with the recent messages of the same channel or thread, when character replies are enabled. It translates a message only when a member picks it from the message's Apps menu. It ignores messages from other bots and webhooks for link previews.

## How information is used

Message text is prepared for speech. The default voice is a Microsoft Edge Read Aloud voice, so unless a member selects one of the local voices, the prepared text is sent to Microsoft. Supertonic and VOICEVOX run locally in the service operator's deployment; Edge also receives the prepared text when a selected local backend fails before returning any audio. The generated audio is played in the connected Discord voice channel.

When the service operator enables the character-reply feature, the text of a message that calls Kuyo is reduced to remove Discord identifiers, links, code blocks, and spoiler-hidden text, and limited in length. For model-generated replies, the current message and the recent conversation of the same channel or thread are sent to the model provider the service operator has configured: the OpenAI Responses API or the Anthropic Messages API. The recent conversation is read from Discord when Kuyo answers: up to 20 messages posted before the current one within the previous 30 minutes, from every member, including messages that did not call Kuyo, and Kuyo's own replies. Each is reduced in the same way and limited to 200 characters, and is sent with its author's server display name, the display name of the member it replies to, the number of images attached, and which of Kuyo's two reactions she left on it. Mentions of members are replaced with their display names; Discord IDs are not sent. Messages from other bots and webhooks are left out, and recognized encoded text is replaced with a marker. Because the conversation is read as it currently appears on Discord, an edited message is sent as edited and a deleted one is not sent. Messages from other channels or threads are never included. Recognized technical text-decoding requests, and immediate requests to reformat that encoded text, receive a local character reply without a model call. Encoded text that appears in the recent conversation is sent only as a generic marker, and a request about it right after receives the same local reply. The configured model writes Kuyo's short reply in the language of the message. A message the member replies to is also included, reduced in the same way and limited to 500 characters, with its author's display name, when it is in the same channel or thread; it is read from Discord when not already cached. Application code checks the reply length (100 characters by default), limits number sequences to four digits per run and eight in total, and rejects sensitive numbers, links, or mentions. Harmless emoji and presentation marks are removed while retaining the words. Invalid output receives a localized format-error notice; unavailable generation and daily budget exhaustion have separate notices. These failure notices are not kept as Kuyo's last reply. The application does not reject an otherwise valid message or reply solely because it contains sexually explicit wording. Model decisions labeled meta use curated lines, as do knowledge_unknown decisions whose text contains a number; other unknown-knowledge, unfamiliar-topic and unverified-sports replies retain the model's contextual response. Quoted material includes whether it was authored by the member or Kuyo. API refusals, incomplete output, malformed output, and connection failures are handled separately. On OpenAI, API response storage is disabled; Anthropic offers no such request setting and handles API data under its own commercial terms and privacy policy. A one-way identifier derived from the Discord user ID with a secret key is sent for abuse prevention; the user ID itself is not sent. The same model response may also pick one of two fixed emoji reactions, which Kuyo adds to the member's message; no additional information is sent for this. Calls without text are answered locally, and messages that do not call Kuyo are sent to the model provider only as part of a later call's recent conversation.

When the service operator offers Kuyo memory and a member turns it on in `My settings` on the settings website, the same model response may also pick one short fact the member said about themselves, such as what to call them, things they like, or a hobby. The model is told not to keep sensitive information such as addresses, contact details, school or workplace, health, sexual content, religion, political views, money, or passwords, or what members say about other people. A fact is stored in the member's own words: application code limits it to 60 characters, requires it to be copied from the current unquoted message, and checks for links, mentions, sensitive numbers, known sensitive wording including where someone studies, works or lives, and instruction-changing content. These wording checks are conservative filters, not a guarantee of semantic classification. Memories are kept with their source channel, up to 20 per server, the oldest being removed first; only facts from the current channel are sent to the model provider with later mentions there. A correction can replace one existing fact from that channel atomically, and only together with a newly grounded fact. Older memories without a source channel remain visible in settings but are not automatically sent to the model provider. Members who have not turned memory on are never asked about, and nothing is saved for them.

Images attached to a message that calls Kuyo are never sent to the model provider. Only their number is sent, so that Kuyo does not pretend to have seen them.

When the service operator enables translation and a server has not turned it off, any member can right-click a message, including another member's, and choose `Translate with Kuyo`. The text of that message is sent to the model provider the service operator has configured (the OpenAI Responses API or the Anthropic Messages API) with an instruction to translate it into the member's chosen language, or their Discord language when they have not chosen one. Mentions, custom emoji, links, code blocks, and timestamps are replaced with numbered placeholders before sending, so user, role, and channel IDs and link addresses are not sent; they are put back into the translation afterward. A message already written in the target language's own script, or one with no words, is not sent. A one-way identifier derived from the requesting member's Discord user ID with a secret key is sent for abuse prevention; neither the requester's nor the author's user ID is sent. On OpenAI, API response storage is disabled. The translation is shown only to the member who asked, with the author's display name and avatar, and is not posted to the channel. Choosing another language or translating again reads the message from Discord again, so an edited message is translated as it now reads and a deleted one is not translated.

For link previews, Kuyo sends the author’s server display name, Discord avatar URL, and accompanying text to Discord through an application-owned webhook, with rewritten public-post URLs for Discord to render through the services in [the provider list](UNFURL_PROVIDERS.md). Nicknames and avatars identify the original sender; the message remains an application message. When it has Manage Messages permission, Kuyo removes the original after sending and recording its replacement and rechecking the original. Messages containing attachments or other context that cannot be preserved, messages that call Kuyo, oversized copies, and originals changed during copying are retained. The post identifier and any supported image selection are visible to Discord and the preview provider; Kuyo does not send the surrounding message text or Discord author ID to those providers. Their services may retrieve and cache the referenced public content.

The mini-games opened with `/game` use the Discord user IDs of the people playing, the titles, results, and candidate names an organizer types for a ladder or winner draw, and, for a word chain, the words they type. A message in a channel with a running word chain is examined only for a Korean word; anything else is left alone and is neither judged nor answered. When the service operator has configured a dictionary key, a single word played into the game, or the single syllable the next answer must begin with, is sent to the National Institute of the Korean Language's 표준국어대사전 open API to check that it is a noun and to find Kuyo an answer. No Discord server, channel, user identifier, or surrounding message text is sent with those lookups. Rock-paper-scissors, the ladder game, and winner draws send nothing outside Discord.

For posts, Kuyo sends the author's server display name, Discord avatar URL, role color, the text they wrote, and the images they attached to Discord through an application-owned webhook, so the post appears under the author's name. Only members with Manage Server can write, edit, or delete posts. Images are checked to be PNG, JPEG, GIF, or WebP and passed to Discord; when a post is edited, the images it keeps are downloaded from Discord and uploaded again with it. Kuyo does not store images itself.

The settings website uses Discord sign-in with the `identify` and `guilds` permissions. At sign-in it reads your Discord user ID and the IDs of the servers you belong to, then revokes the Discord access token; the token is not kept. Your name and avatar are looked up through the bot when a page needs them and are not stored. Each time you open or change a server's settings, Kuyo asks Discord whether you are still a member and still have Manage Server. A voice preview on the website speaks one fixed sample sentence, never text you wrote; for a Microsoft Edge voice, only that sentence is sent to Microsoft, and the audio is not stored.

Kuyo does not sell personal information, show advertising, or use message content for tracking. Apart from the memory a member chooses to turn on, Kuyo does not create user profiles.

## Storage and retention

Apart from the text of posts, Kuyo does not persist raw message text, generated audio, or conversation history to its database or disk; Kuyo memory keeps only the short facts described above. Completed speech may be held in a size-limited process-memory cache for up to 15 minutes to avoid synthesizing an identical line again. Cache keys are one-way hashes rather than readable message text, and cached audio is removed on expiry, eviction, or restart. When character replies are enabled, the recent conversation is read from Discord for each reply and is not kept after the reply is written. Kuyo keeps only her own last reply to each member in each channel or thread in process memory, so a reply that has not yet appeared on Discord is still part of the next one; it stops being used 30 minutes after it was said and is removed within about a minute once 30 minutes pass without the member addressing Kuyo there. It is also cleared when Kuyo leaves the server, when the bot restarts, or when the member deletes all personal data. When a member deletes all personal data, the messages they wrote before then, and Kuyo's replies to them, are left out of every recent conversation for the following 30 minutes, after which they are older than the conversation Kuyo reads; this exclusion is held in process memory and does not survive a restart. A reply still being written when the member deletes their data, turns memory off, or deletes a memory is stopped and not posted.

Translations are held in a size-limited process-memory cache for up to one hour, so the same message asked for again is not sent a second time. The cache key is a one-way hash of the placeholder-masked text and the target language; the original text is not kept for the cache, and the cache is cleared on restart. A member's chosen translation language is stored with their user ID until they change it back or delete all personal data. Kuyo counts translations per day in total, per member, and per server to bound their cost; only the daily total is written to the database, and the per-member and per-server counts stay in process memory.

Mini-games are held in process memory only. A game keeps the participants' user IDs, the words already played, the hands chosen, and any titles, results, and candidate names entered for it, and it is discarded when the game ends, when it is left alone (three minutes for a word chain, ten for the others), or when the bot restarts. Dictionary lookups are cached in memory for up to one hour. Nothing from a game is written to the database, and game results stay in the channel message like any other message.

Server settings and pronunciation entries are kept while the bot remains in the server. They are deleted when the bot is removed. Voice preferences and custom join greetings and leave farewells are shared across servers that use Kuyo and remain until the user deletes them or the service is discontinued. Kuyo memories are kept until the member deletes them, turns memory off, or deletes all personal data; a server's memories are deleted when the bot is removed from that server, and a channel's when that channel, or the channel a thread belongs to, is deleted.

Link-preview records contain original/preview message IDs, server/channel/author IDs, dismissal/replacement flags, and a SHA-256 fingerprint of the message text and normalized links. Raw URLs, media, avatar URLs, and webhook tokens are not stored in the database. Dismissal records prevent a removed preview from reappearing after edits or restarts. When Kuyo has replaced and removed an original, its tracking record remains until the replacement is deleted, the channel is deleted, or Kuyo leaves the server. For originals that remain, records are removed when Kuyo processes deletion of the original message or channel, or leaves the server; removing only the preview keeps a dismissal record. Events missed while offline are not replayed. For removal of remaining tracking records, contact the server administrator.

A post is stored with its message, server, channel, parent channel, and author IDs, the tab name, title, body, and image file names of each of its pages, its link buttons, an edit counter, and the user ID of whoever last edited it and when, so it can be edited and a manager who edits another's post is not hidden behind the writer's name. It is deleted when the post is deleted, when its channel or thread is deleted, or when Kuyo is removed from the server. When the author deletes their data, the record keeps only the post's message, server, and channel IDs, with the author ID and text removed; when someone who edited a post deletes their data, their user ID is removed from it. The post stays in the channel until a server manager deletes it, and a manager can rewrite it.

A website sign-in is kept as a random session cookie. The database stores only a one-way hash of that cookie, your user ID, the server IDs read at sign-in, and an expiry time. Sessions end after seven days, when you sign out, or when you delete all personal data, and expired sessions are removed automatically.

The service operator keeps copies of the database as backups, readable only by the server administrator, for up to 30 days; website sign-ins are left out of them. Settings you delete remain in backups made before the deletion until those backups expire. So that restoring a backup cannot bring deleted data back, each deletion you or a server manager make (deleting all personal data, turning memory off, deleting a memory, clearing a greeting, farewell, voice, or translation language, or deleting a post), and each deletion that follows a channel being deleted or Kuyo being removed from a server, is also recorded in a separate file for 35 days with what was deleted (your user ID, the memory number or language, or the post's message, channel, or server ID) and the time, never the deleted content. After 35 days only the entry's sequence number is kept. Deletions made after a restored backup are applied again when the service starts.

Limited service logs may contain server IDs, Discord user IDs, timing information, and error messages. Kuyo itself does not write message text to these logs. The exception is the local VOICEVOX engine: it receives the text to read in its request address and records that address in its access log, which cannot be turned off, so the text of messages read with a VOICEVOX voice can appear there. That log stays inside the operator's deployment and is rotated after at most 30 MB. Logs are automatically rotated and used only to keep the service reliable.

## Service providers

Kuyo relies on the following providers:

- [Discord](https://discord.com/privacy) for messages, commands, voice connections, and link previews
- The external services in [the preview provider list](UNFURL_PROVIDERS.md) for supported social-link previews
- [Microsoft](https://privacy.microsoft.com/privacystatement) for selected Edge voices and local-backend fallback speech
- [OpenAI](https://openai.com/policies/privacy-policy/) or [Anthropic](https://www.anthropic.com/legal/privacy), whichever the service operator has configured, for writing Kuyo's short character reply and for translating a message a member asks to translate, each only when the optional feature is enabled
- The National Institute of the Korean Language's [표준국어대사전 open API](https://stdict.korean.go.kr/openapi/openApiInfo.do) for checking a word in the word-chain game, only when the service operator has configured a key

Kuyo also runs Supertonic and [VOICEVOX](https://github.com/VOICEVOX/voicevox_engine) inside the service operator's own deployment. Text processed by these local engines is not sent to their providers as a speech-generation request, although first-time model installation may download model files from their distributors.

These providers may process information in countries outside your own and apply their own privacy terms.

## Your choices and rights

Use `My settings` on the settings website, which `/kuyo` links to, to see or delete the voice settings, custom join greeting, custom leave farewell, and Kuyo memories linked to your Discord account. Memory is off until you turn it on, and turning it on applies to your account in every server where you mention Kuyo; each server's memories are still kept separately, and each memory is used only in the channel where it was said. You can delete single memories, and turning memory off deletes all of them in every server. While the operator has paused memory, Kuyo neither saves nor uses memories, and you can still see, delete, and turn off what was saved. Deleting all personal data also clears Kuyo's short-term memory of you and leaves your earlier messages out of her recent conversations, in every channel and server at once, ends every website sign-in, and deletes the stored text of your posts. To remove a post itself from the channel, ask a server manager to delete it.

You can also choose the language translations are shown in, or go back to following your Discord language, under `My settings`. Server administrators can turn translation off for their server on the server's page.

Server administrators can view or remove custom pronunciation entries from the server's page on the settings website. Removing Kuyo from a server deletes that server's settings and pronunciation entries.

Server administrators can disable link previews on the server's page on the settings website. The original author or a member with Manage Messages can delete the entire replacement, including text, links, and embeds, using the Delete message button. An older Hide preview button first updates to the new label and explains the change; pressing the new button deletes the message. Tracking and dismissal state remain until the applicable message/channel/server cleanup described above. Prefix a link with `!`, surround it with angle brackets, or use code/spoiler formatting to prevent automatic conversion.

For any other privacy request, contact the administrator who added Kuyo to your Discord server. Do not post personal information in a public issue or channel.

## Age requirements

Kuyo's character-reply feature is intended for adults. Server administrators should restrict access to suitable members and channels. Kuyo is not directed to children.

## Changes

This policy may be updated when Kuyo changes. The effective date at the top will be revised when material changes are made.
